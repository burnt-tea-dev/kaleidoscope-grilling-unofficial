# Oil-specific brush and oil-pot held rendering

Candidate based on G150 / `aa091a1e91035d1510b579af11254a9bc9f86e6b`. This is a source-derived rendering repair, not a release or Minecraft-client acceptance receipt.

## Failure and repair

The successful Cookery oil-pot branch animated the equipped pot; Java renders an oil-specific brush. The candidate now publishes a render-only, per-hand 20-tick session **after** the oil/Grill transaction succeeds. An exhausted pot is captured as the resulting empty pot. No ItemStack replacement, inventory restore timer, helper entity, extra player property, or resource-pack player override is introduced.

A stable oil-pot attachable always applies to player-held `kaleidoscope_cookery:oil_pot` and `oil_pot_filled`. One render controller selects eight generated-sprite shells: empty, host fat, canola, secret chili, premium chili; then the three corresponding brushes. Idle and brush each use their own exact source texture and alpha-boundary geometry. Model and texture share one index. Missing/invalid transport falls back to the corresponding ordinary pot, never an invisible model. The inactive hand remains its own pot. Both source Cookery BP item definitions omit `minecraft:allow_off_hand`; this patch does not change host inventory eligibility. The offhand route handles an already equipped offhand stack and is editor-tested, not a claim that players can place these pots in offhand through native inventory.

The existing 32-property presentation bus is reused. Marker 225 means brush, word 1..60 encodes oil type and elapsed tick; marker 226 means idle pot, word 0..4 encodes idle type. The existing invalidation-before-write / ready-last publication prevents accepting incomplete payload submissions. Native property replication is not claimed atomic.

Switching item, changing main-hand slot, changing stack metadata, changing dimension, cancellation, death/respawn, disabling the option, and the 20-tick endpoint end the session. A replacement item's presentation provider is never overwritten. A dedicated oil-pot clip evaluates Java's full-interval `sin(clamp(progress)*2π)` without entrance/exit retiming. The slot-bound sprite hierarchy separates the FP camera/socket inverse, source translation, X/Y/Z factors and generated item display. TP uses source arm angles plus item-local Z rotation before the display transform; its shoulder-offset correction uses the live arm inverse. Both the player arm and attachable read the same per-hand authoritative elapsed-tick packet. They evaluate the same source sine at 20 Hz, without independent local phase clocks. This intentionally trades Java partial-tick smoothness for deterministic shared phase. The session still ends after 20 server ticks; a finite two-second player clip is only a lost-marker safety ceiling. An unchanged attachable packet also expires two seconds after its last update and falls back to its ordinary idle pot (at worst about three seconds after start if only the final marker update is lost). New packet progress resets that watchdog. The controlled player clip stops through the per-hand marker and exact item-name check. The physical-brush legacy clip stays byte-identical. Initial presentation-write failure cancels the session; it cannot revive next tick underneath an uncontrolled legacy clip. Animation-start failure also cancels substitution. Physical brush-item gameplay is unchanged.

`enableOilBrushVisuals` defaults to true and can disable transient substitution through the existing Grilling config command. It does not remove the source-derived idle attachable.
