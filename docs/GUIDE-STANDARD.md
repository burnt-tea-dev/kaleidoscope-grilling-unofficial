# 煙火指南維護規範

烟火維持森羅廚房既有指南內的一個章節，由唯一 publisher 使用公開 Guidebook API 註冊。不得新增實體指南書、平行導覽 UI、宿主全檔替換或翻譯內的玩法補丁。

## 分類與物品頁

保留目前六個根類與順序：工作站、食物百科、工具與裝備、儲存與實用功能、耕作與收成、進度與指南物品。食物子類按實際製程分組；同一物品的生熟狀態、用法、取得與成品效果共用一頁。酒館七個釀酒入口不逐字套用於煙火。

沿用宿主「大類 → 帶圖示與條目數的子類 → 物品頁」，原生 Preparation 介面呈現食品配方。設備頁解釋操作，不能要求不存在的配方卡。宿主 v1 最多 32 分類，只有一層父類；不把獨立章節的分類數相加。單條子類直達與固定來源順序是家族的一致性目標；宿主缺少這項能力時記錄限制，不私改 renderer。

## 真實可用性與語言

- 每個生存取得缺口在相應材料／成品頁的第一段標明；Java 做法須標為原版參考，不能先承諾可用再於頁尾否認。
- 起步用目前源碼具有取得路徑的魚串，列出空串、副手、油、基礎調料、點火、四翻、撒料與食用門檻。完整生存遊玩仍需真人驗收。
- 繁中、簡中、英文名稱與操作說明必須完整；熱食等 runtime lore 使用 RawMessage 翻譯鍵，保留使用者 lore 與物品資料。
- 使用公開宿主支援的製程名稱取得宿主本地化；API v1 不支援製程的多語 map。不能用無效欄位假裝已支援。材料名稱由宿主優先顯示的限制須記錄，宿主修復先做乾淨原包重現與維護者回饋。
- guide catalog、產生的 payload／lang 與包版本保持一致，變更輸出要換版並追加 release-history。
- `tools/build_grilling_guide.py` 使用 publisher 的同一份 encoder，將 catalog 預編成 `payload.js` 的傳送封包。runtime publisher 只等待宿主 ready 並傳送，不在開服時重算整章；配方、三語、封包順序、重試及資料格式由既有檢查核對。

## 檢查與驗收

`tools/check_grilling_guide.py` 檢查條目／配方／三語／序列化及輸出一致性。隔離 BDS 另核對**實際宿主收到的章節**；兩者都不代表真人導覽已通過。Windows／觸控、三語切換、多人隔離、返回路徑與完整取得流程分開驗收。禁止模擬玩家。
